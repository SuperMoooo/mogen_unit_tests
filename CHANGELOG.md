# [1.2.0]

## Features

- **`family` notifier support** — `FamilyAsyncNotifier`/`FamilyNotifier` (and `AutoDispose` variants) are now detected, the family argument type is taken from the second generic, a `familyArg` value is declared once, and every read uses `provider(familyArg)` (including `.future`/`.notifier`). Family _dependencies_ captured as `otherProvider(arg)` have the call argument stripped before overriding, and non-notifier family dependencies are overridden via the family factory (`overrideWith((ref, arg) => mock)`).
- **Runtime-safe mocks for notifier dependencies** — a notifier dependency is no longer mocked with a bare `extends Mock implements X` (which crashes with `MissingStubError` on first read, because Riverpod wires notifiers through library-private members). The mock now extends the dependency's real base class (`class MockX extends AsyncNotifier<S> with Mock implements X {}`) and its `build()` is stubbed in `setUp`, so `await ref.read(otherNotifierProvider.future)` resolves.
- **`registerFallbackValue` generation** — parameter types of every stubbed dependency method are resolved from the interface source, and every non-nullable custom type used with `any()` gets a `registerFallbackValue(Type.empty())` in `setUpAll` (mocktail otherwise throws at stub time). Needed imports are emitted too.
- **Shared-stub hoisting** — a dependency call used by two or more methods is now stubbed once at the end of `setUp` (alongside `build()`'s stubs) instead of repeated in every success test.
- **Overwrite protection + `--force`** — an existing test file without the `GENERATED BY mogen_unit_tests` marker is treated as hand-maintained and skipped with a warning; `--force` overwrites it anyway.

## Fixes

- **Error tests could never pass when the method shared a call with `build()`**: the throw stub was skipped as "already stubbed in setUp()", leaving nothing throwing while the test asserted `error isNotNull`. Error tests now initialise the notifier first (success stubs still active), then re-stub _every_ call the method makes with `thenThrow`.
- Methods that make no dependency calls no longer get an error test (there is no failure to simulate, so it could never pass).
- Synchronous dependency methods are now stubbed with `thenReturn(...)` instead of `thenAnswer((_) async => ...)`, which produced a runtime `TypeError`; `Stream`-returning and `void` methods get matching treatment. Cross-feature repositories now also resolve their return types (the interface is located on disk instead of assumed in the consuming notifier's feature), so their stubs return real values instead of `null`.
- Plain (synchronous) `Notifier` state assertions no longer emit `.requireValue`, which only exists on `AsyncValue` and didn't compile.
- Entity/model imports are now verified on disk across all features (entities, models, states) before falling back to a guess, fixing wrong paths for cross-feature types.
- Getters, setters, static members and operators are no longer scaffolded as callable test methods (`.isReady()` didn't compile).
- Classes extending `ChangeNotifier`/`ValueNotifier` under `presentation/notifiers/` are no longer mistaken for Riverpod notifiers (exact base-class matching).
- Acronym class names now produce correct snake_case file names (`APIClient` → `api_client`, previously `a_p_i_client`).
- The success-message assertion is only generated when the method body actually mentions the state's success field, instead of failing for every method that doesn't set one.
- Field-declared notifier/cubit/bloc/viewmodel dependencies are now detected (the parser's suffix list matches the generator's).
- Duplicate notifier class names across features now emit a warning instead of silently shadowing each other in dependency resolution.
- CLI banner no longer claims `AsyncNotifier`-only support, and the printed output path matches the real `test/unit/features/` destination.
